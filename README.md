# Blueprint

Playwright test automation framework for the Hotel Web App. The project supports API checks, browser-based tests, and database validation against MariaDB/MySQL.

## Requirements

- Node.js
- npm
- A running Hotel Web App at the configured base URL
- MariaDB/MySQL running on `localhost:3306`
- Database `hotelwebapp`

## Installation

```bash
npm install
npx playwright install
```

Playwright browser installation is required once after installing the project. On
Linux, install the browser system dependencies as well if Playwright reports
missing shared libraries:

```bash
npx playwright install --with-deps chromium
```

## Configuration

### Application URL

Environment URLs are defined in `config/env.ts`. The current configuration uses:

```text
http://localhost:3000
```

### Database

Database settings are defined in `config/database.ts`:

- Host: `localhost`
- Port: `3306`
- Database: `hotelwebapp`
- User: `root`

Update the credentials and host when your local or remote database differs.

### Test data

Test data is loaded from the environment-specific directory:

```text
data/<environment>/data.json
data/<environment>/userInfo.json
```

Use lowercase environment names such as `sit` or `uat`.

## Running Tests

The test runner reads the `ENV` environment variable. Available test data
folders currently include `sit` and `uat`.

### macOS and Linux

Run the current profile test in Chromium:

```bash
ENV=sit npx playwright test tests/profileWebPage.spec.ts --project=chromium
```

Run with the browser visible:

```bash
ENV=sit npx playwright test tests/profileWebPage.spec.ts --headed --project=chromium
```

List tests without running them:

```bash
ENV=sit npx playwright test tests/profileWebPage.spec.ts --list --project=chromium
```

Run tests by tag:

```bash
ENV=sit npx playwright test --grep @e2e
```

Run all configured browsers:

```bash
ENV=sit npx playwright test
```

### Windows PowerShell

Set the environment for the current PowerShell session before running a test:

```powershell
$env:ENV = "sit"
npx playwright test tests/profileWebPage.spec.ts --project=chromium
```

Run with the browser visible:

```powershell
$env:ENV = "sit"
npx playwright test tests/profileWebPage.spec.ts --headed --project=chromium
```

Run all tests:

```powershell
$env:ENV = "sit"
npx playwright test
```

### Windows Command Prompt

Set the environment variable and run a test in the same command window:

```bat
set ENV=sit
npx playwright test tests/profileWebPage.spec.ts --project=chromium
```

Run with the browser visible:

```bat
set ENV=sit
npx playwright test tests/profileWebPage.spec.ts --headed --project=chromium
```

Run all tests:

```bat
set ENV=sit
npx playwright test
```

Replace `sit` with `uat` when you want to use the UAT test data.

## Reports

### Playwright HTML report

The HTML report is generated by Playwright. Open it with:

```bash
npx playwright show-report
```

### Allure report

Allure results are written to `allure-results` after a test run. Generate a
report from those results:

```bash
npx allure generate allure-results --clean -o allure-report
```

Open the generated report:

```bash
npx allure open allure-report
```

Alternatively, serve the report directly without creating a separate output
directory:

```bash
npx allure serve allure-results
```

The Allure commands are the same on macOS, Linux, Windows PowerShell, and
Windows Command Prompt. Run them from the project root. If no results are
available, run a Playwright test first.

## Project Structure

```text
config/                 Environment, endpoint, and database configuration
data/                   Environment-specific JSON test data
pages/                  Playwright fixtures and page objects
tests/                  Playwright test specifications
utils/api/              API helper classes
utils/database/         Database helper classes
utils/common_function.ts Shared decorators and database query helper
playwright.config.ts    Playwright configuration
```

## Notes

- The database layer uses `mysql2`, which is compatible with MariaDB.
- Do not use the `mssql` driver with the MariaDB connection on port `3306`.
- The API health check and direct database query use separate connections. A passing health check does not guarantee that the test runner's database credentials are valid.
